## 8.1 Alcance de este documento

CMEDriver es un **MVP académico**. Durante la elaboración de los entregables (requerimientos, stack, arquitectura, MER, BPMN y C4) se verificó la documentación contra el código y se encontraron limitaciones, brechas de seguridad, reglas de negocio aplicadas de forma parcial y pendientes de despliegue.

Este documento las **registra de forma deliberada** en un solo lugar, sin duplicados, junto con una mejora concreta para cada una. **No se corrigieron en el código en esta entrega por decisión del autor**: el objetivo de la entrega es documentar fielmente el sistema tal como está, y cada corrección se planifica en la hoja de ruta de la §8.4. La única excepción son tres afirmaciones desactualizadas de [../11-manual-distribucion.md](../11-manual-distribucion.md), corregidas porque solo eran documentación (LIM-32). En la revisión final (Fase 7) también se corrigieron, solo en documentación, varias inconsistencias entre los entregables (ver LIM-33); ninguna limitación de código cambió de estado.

Todas las evidencias se verificaron en el código del repositorio. La suite automatizada del backend (96 pruebas, todas en verde) **no** detecta estas limitaciones, porque ninguna prueba cubre esos casos.

**Convenciones**

- **Prioridad.** *Alta*: debe resolverse antes de cualquier uso con datos u operación reales. *Media*: afecta la calidad, la consistencia o la operación, pero tiene mitigación. *Baja*: mejora de mantenibilidad o de coherencia.
- **Origen.** `H-xx` es un hallazgo de [01-requerimientos.md](01-requerimientos.md) §8. "Fase N" es la fase de la entrega en la que se detectó: 1 requerimientos, 2 stack y arquitectura, 3 MER, 4 BPMN ([05-bpmn.md](05-bpmn.md)), 5 C4, 6a README y 6b trazabilidad ([07-trazabilidad.md](07-trazabilidad.md)), 7 revisión final ([00-guia-de-entrega.md](00-guia-de-entrega.md)).
- **Evidencia.** Se indica como `archivo` → `clase/función`, con rutas relativas a la raíz del repositorio.

## 8.3 Servicios simulados (limitación de alcance)

No son defectos: son decisiones de alcance tomadas por la falta de credenciales y de presupuesto en un proyecto académico (RES-06, RES-07, RES-08, RES-15). En los tres casos la **arquitectura de integración es real**: el proveedor está detrás de una interfaz, y conectar el real cambia un archivo y la configuración.

| ID | Servicio | Estado actual | Qué no hace | Cómo se conectaría el real |
|---|---|---|---|---|
| SIM-01 | **Modelo de lenguaje (LLM) del chatbot** | `MockLLMClient` en `backend/chatbot/llm.py`: reconoce la intención por palabras clave y completa los datos con una máquina de estados. Las *tools* (`tool_listar_productos`, `tool_consultar_agenda`, `tool_crear_recoleccion`, `tool_crear_compra`) y el historial con `function_call` son reales. | No entiende lenguaje natural libre. Las fechas deben escribirse en formato AAAA-MM-DD. | Implementar un cliente con la misma firma `responder(conversacion, mensaje_nuevo) -> dict` que llame a la API de un proveedor (p. ej. la Messages API de Anthropic con *tool use*), declarando como herramientas las cuatro funciones existentes. La API key iría en una variable de entorno (p. ej. `LLM_API_KEY`) y un selector de proveedor permitiría usar el mock en pruebas. |
| SIM-02 | **Pasarela de pagos** | `MockPaymentProvider` en `backend/payments/provider.py`: aprueba alrededor del 90 % y rechaza alrededor del 10 % al azar, sin mover dinero. Se obtiene con la fábrica `obtener_proveedor_pago()`. | No hay cobro real, ni captura de tarjeta, ni conciliación. | Implementar `PaymentProvider.procesar(pago)` para Wompi o PayU (sandbox primero), con credenciales por variables de entorno, y elegir el proveedor en `obtener_proveedor_pago()` según la configuración. Nunca almacenar datos de tarjeta (usar el *checkout* tokenizado de la pasarela). |
| SIM-03 | **Correo electrónico** | `EMAIL_BACKEND = console.EmailBackend`: el correo de restablecimiento de contraseña se imprime en la consola del servidor. | El usuario final no recibe el correo. | Configurar por variables de entorno `EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend` con las credenciales SMTP de un proveedor transaccional (SendGrid, Amazon SES), además de `DEFAULT_FROM_EMAIL` y `FRONTEND_URL` del dominio real.
